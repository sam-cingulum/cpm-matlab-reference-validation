Every original MATLAB Qy operation was bitwise repeated with the same numeric result, normal completion. Numerically important discovery: the same cancellation pair (`a,b`) yields different floating-point results in output column 1 versus output column 2 in **896/14,155** cases. Thus a single original GEMV addition tree is NOT correct for the two-column matrix, even on the SAME CPU. Naively mixing the three triple outcomes from both columns yields only **13,651/14,155** single-winner triples; this apparent incompatibility is real output-column context, not a defective original algorithm.

Separating the columns yields two distinct **internally consistent fully rooted binary addition trees** at **all 12 tested lengths: 9,10,11,12,15,16,17,18,23,24,25,32**. The exact tree reconstructed solely from original-source-disclosed cancellation bits matches all **56,620/56,620 original numeric triple output values** on each original host, and the exact same pair of trees independently emerged on both original MathWorks AMD hosts. Tested on *different* original-MATLAB random matrix product inputs (not used for tree inference), the per-column binary summation trees with separately rounded products reproduced **480/480 true original Qy binary64 values**. With previously precommitted independent Rust Q, another two previously disclosed real original MATLAB `robustfit` raw-input cohorts independently scored **288/288 original Qy values each** for the 12 supported lengths. Those are source-disclosed retrospective checks, not a new prospective original-source certification.

Original-source exact data, complete original numeric output SHA256, original CPU and MathWorks vendor fingerprint and both original-uncompressed and archived-compressed SHA256 manifests are preserved for both runs. No proprietary MATLAB binaries distributed.
